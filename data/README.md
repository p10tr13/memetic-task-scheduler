# Benchmark data

Task graphs for the memetic scheduler, in Kasahara **STG** format (first line =
real task count `n`; then `n+2` rows `task_id  proc_time  num_preds  preds...`
including the two zero-duration dummy nodes entry `0` and exit `n+1`; `#` comment
header with metadata follows). All graphs are the **zero-communication** model
(task durations + precedence only), matching the project.

```
data/
├── example.stg     # tiny hand-authored DAG for the MILP demo (src.main)
├── optima.csv      # published optimal/best-known makespans for the Kasahara graphs
├── kasahara/       # 10 real Kasahara STG graphs (downloads)
└── synthetic/      # 10 generated synthetic graphs (make data)
```

## `kasahara/` — real STG graphs

From the Standard Task Graph Set, Kasahara Lab, Waseda (Tobita & Kasahara,
*J. Scheduling* 5(5):379–394, 2002). <https://www.kasahara.cs.waseda.ac.jp/schedule/>
Random graphs from `ver2/rnc*.tgz`; application graphs from `robot/sparse/fpppp.tgz`.
Selected to span size and density. Files are named `<name>_t<tasks>_p<NNN>`, where
`<name>` is the STG source name (random index `rand####`, or the application name),
`<tasks>` is the real task count, and `NNN = round(real edge density × 100)` with
real edge density `= real_edges / (tasks·(tasks−1)/2)` (the STG "Probability").
`M` = campaign processor count. Each file's own `#` header also records its origin.

### `optima.csv`

Published optimal / best-known makespans from the STG "Optimal Schedule Lengths"
tables (`optim_v2.html`), which cover random sizes **50 / 100 / 300** at
M = 2, 4, 8, 16. A single value is a **proven optimum**; a `lower-upper` range
means optimality was not proven within the solver's 10-minute limit (lower =
bound, upper = best schedule found). Sizes ≥ 500 and the application graphs have
no published optimum, so the campaign uses the computed lower bound
`max(⌈total_work / M⌉, critical_path)`. The `50/rand0000` and `300/rand0000` rows
are verified; the other four random-graph optima are single-pass extracts
(`verified=no`) — spot-check them before quoting in the report.

## `synthetic/` — generated graphs

Reproducible synthetic DAGs of various size (15–150 tasks) and density,
generated by `scripts/build_data.py` (`make data`) from the fixed-seed
`_SYNTHETIC_SPECS` in `src/experiments/instances.py`; the campaign generates the
same instances in memory, so the files are an inspectable mirror. `nodes`/`edges`
include the two dummy nodes; `density = edges / nodes²`; `M` is the campaign
processor count; `req. density` is the edge density passed to the generator.
Instances with ≤ 30 real tasks get an exact MILP reference, the rest a lower bound.

Files are named `syn_t<tasks>_p<NNN>` (same `p` convention as the Kasahara graphs).
`nodes`/`edges`/`density` include the two dummy nodes; `req. density` is the edge
density requested from the generator.

## `example.stg`

A tiny hand-authored DAG (12 real tasks + 2 dummies) kept at the data root. Small
enough to solve to proven optimality with the MILP solver, so it drives the
`python -m src.main` optimality-gap demo. Not part of the campaign set.
